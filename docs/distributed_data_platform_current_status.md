## 2. 架构与数据边界

平台采用 **统一管理、分散存储、就地计算**：

```mermaid
flowchart LR
    U[用户浏览器] --> W[Server A：HTTPS 控制台]
    W <--> M[(账号、范围、任务、审计)]
    W <--> R[(远端 Viewer 与结果缓存)]
    W <--> A[H100 / Server B：Agent]
    A <--> D[(节点本地原始数据)]
    A --> O[(独立输出数据集)]
    A --> R
```

Server A 同时承载独立 dev/prod 服务、数据库与状态；Agent 的环境、数据根及输出根由各自配置登记。
工作区源码、不可变发行包、安装后的 `current`、执行暂存、发布缓存是不同对象。详情见
[存储位置](data_platform_storage_locations.md)。平台不合并各服务器磁盘，也不把原始数据集中复制到 Server A。

支持 LeRobot v2.1/v3.0、UMI 和已适配 GenDAS MCAP。源数据默认保护；预处理、转换和物化生成
独立输出。Viewer 账号只读；operator/viewer 的数据范围限制读取与任务输入，data_manager 的写范围
与 Linux 权限、Agent roots、源修改开关共同生效。缓存标注回传不等于源 Parquet 写回。

## 4. Data Intelligence：近期能力与操作

| 内容 | 当前实现与使用边界 | 提交依据 |
| --- | --- | --- |
| Data Inspect | 本地 Parquet、远端已发布 CSV 的有界只读预览，兼容 `.csv.gz`，默认全选字段；缓存不等于实时源数据 | `17346fdf`、`4508c50f` |
| Quality 检查 | 控制一致性、任务/阶段标注、关节运动、末端运动、数值有效性、图像/视频六类，按实际信号启用 | `8e3fd455`、`4608f388` |
| Quality 报告与复核 | Data Report 展示数据总量、已检查范围、问题及媒体覆盖；连接 Episode Viewer 并保留复核草稿 | `86ac1590` |
| DVT2 默认处理 | 兼容 DVT 表单与关节检查默认 DVT2；UMI 保留位姿与时间分段路径，不套用关节阈值 | `add8e481`、`104044e6` |

质量判断按“问题类型 × 可用信号”组织。EEF 是整体 Quality 的一部分；关节与末端数据也能共享数值、
标注和媒体检查。末端突跳、模糊、冻结和文本格式提示是人工复核候选，零 flag 不证明未检查数据合格。
先运行检查、查看报告及覆盖，再在 Viewer 复核并保存 Keep/Exclude/Needs review 或修复建议。
检测不能直接驱动源数据删除。具体步骤见[页面手册](data_platform_page_user_guide.md#54-data-curation--quality-review)。

现有时序标注继续使用共享任务表单和独立 Review，支持批量 episode、可选信号与数据集本地实验结果读取。
模型审核和人工批准分别记录；关闭信号时不提供 Action/State 证据。已接收任务不会因离开页面而取消。
版本化 Curation 保留草稿 revision、Manifest 审批顺序与 episode lineage，最终物化为新数据集。

## 5. 日常操作顺序

1. **找数据**：核对环境与角色，选择 Server/授权目录；Refresh 看登记，Scan 发现磁盘变化。
2. **理解数据**：Analysis 看元数据，Inspect 看实际记录或缓存，Viewer 看视频和信号；留意同步时间。
3. **处理与复核**：先选小范围运行，检查 Jobs 终态和已发布输出；质量候选在 Viewer 人工复核。
4. **写入与同步**：明确是缓存 sidecar、Curation 草稿还是源数据写回；同步需匹配 revision 的 Agent 确认。
5. **发布**：核对 worktree、全部功能提交与安装基线，在干净集成工作区完成测试后构建，dev 验收批准后
   将同一不可变包用于 prod；已有包重试使用 `--release`，不复用 `--version` 重建。
6. **验收**：Server/Agent 安装身份、有效心跳与能力、维护关闭、正常 TLS、受影响账号流程分别核对。

## 6. 仍需保留的限制

- 存储仍分散；数据副本注册与 lineage 不等于自动跨节点同步原始数据。
- 远端 Viewer 和 Inspect 依赖已发布缓存；过期缓存不能证明当前源数据状态。
- 高可用控制面和对象存储不能从当前架构或历史计划推断已完成。
- 滚动升级仍有短暂维护；`quiescent: false` 的备份不能用于完整自动恢复。
- MCAP 自动恢复只覆盖明确的进程丢失条件；恢复单个任务不证明其他故障都可自动处理。
- 稳定 `.local` 名称与事件驱动地址通知有网络范围限制；开机配置不等于实际重启通知已验收。
- 本次未重新执行功能测试和线上验收；文档证据以已核对代码及本机安装身份为限。
