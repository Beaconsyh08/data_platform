# Data Platform 交互优化设计

本轮以当前部署 `.42` 对应提交 `e4d5f7dd` 为基础，结合页面代码和隔离测试服务的浏览器操作检查。
覆盖 Data Platform、Data Curation，以及 Viewer / Analysis / Review 的共享导航。
本文描述源码设计和验收范围；发布与线上生效状态应另外核对。

## 设计原则

用户始终能回答三个问题：正在处理哪份数据、现在发生了什么、下一步去哪里。
保持现有双 Workspace 和后端权限模型，以共享交互修正为主，不新增任务或审核系统。

| 流程 | 观察到的问题 | 本轮改动 |
|---|---|---|
| 数据发现 | 生命周期标识的实现说明和扫描表单占据首屏；选择后缺少下一步入口 | 折叠阶段解释及已有数据时的发现表单；选中数据后提供 Explore & Viewer、Quality review、Temporal Caption、当前数据 Jobs |
| 数据选择 | 远端卡片禁止 viewer 选择，但顶部选择器允许；loaded 被显示为 ready，容易误认为已有 Viewer | 允许只读选择；状态按实际缓存判断，元数据加载不代表 Viewer 就绪 |
| 工作区切换 | 每次回到工作区都跳到第一个页面/子页 | 当前会话记住每个工作区的页面和每个页面的子页；刷新仍按 URL 恢复 |
| 未选择数据 | 去 Datasets 会离开用户本来想打开的功能 | 空状态直接打开选择器，选择后留在原功能；保留发现新数据的入口 |
| Jobs | 抽屉只列全局任务；排队任务以百分比呈现；筛空后仍可能显示其他任务详情 | 复用 Pipeline Runs 的数据集/状态筛选；明确 Queued/Running/Completed；空列表不显示无关任务 |
| Quality / Annotation / Dataset Build | 未保存的审核在换 Episode、草稿、数据集时会被覆盖；单独填写理由会被丢弃；发布容易漏掉当前表单 | 显示未保存状态；换上下文或替换内容前确认；理由要求选择决定；先保存或重载再发布；只读审核禁用输入 |
| Temporal Caption | 批量提交期间仍能改设置，显示内容可能与实际提交不一致 | 按钮显示任务数量和逐项提交进度，提交期间固定配置；反馈供读屏读取 |
| Viewer / Analysis / Review | 返回入口含糊；禁用入口只能靠鼠标提示 | 明确 Dataset console，标识当前页面；键盘聚焦禁用入口可读原因 |
| 键盘与小屏幕 | 选择器不自动聚焦；弹层 Tab 可逃到背景 | 搜索自动聚焦、Escape 关闭并回焦；Jobs/Admin 弹层限制 Tab 范围并恢复触发点；卡片标识允许换行 |

## 交互约束

- 选择数据与执行任务分开：viewer 可浏览获授权的数据；计算、标注保存及源修改仍由原权限检查决定。
- 排队、已接受、执行完成、已审核保持不同含义。提交成功不显示为任务完成。
- 草稿不自动保存到源数据。确认丢弃前保留原 Episode、草稿和表单；请求失败保留编辑内容。
- 切换 Curation 子页保留审核表单；切换数据集才销毁旧控制器及其监听器。
- 既有 Quality 三步流程、Caption 信号选项、批量幂等与离开页面的提交行为保持原契约。
- 合并 DVT2 默认处理规则：兼容的 DVT 数据可直接运行 S1，高级设置保留 DVT1 选项；
  处理规则与数据来源档案分别保留，UMI 仍使用原生信号规则。

## 后续可评估的工作

较大调整应通过用户实际操作记录确定收益：全平台搜索、浏览器前进/后退的完整表单恢复、
跨页面任务结果直达、统一 Viewer 与主工作台布局。它们需要独立定义 URL、草稿恢复和
结果权限契约。本轮先解决已确认的入口、状态、键盘和内容丢失问题。

## 验收

使用临时 v2.1/v3.0 数据和真实 Flask 路由验证，不对生产数据提交任务。
检查桌面及 390 px 窄屏、只读选择、权限拒绝、工作区位置恢复、Jobs 筛空、键盘焦点、
未保存审核的保留/丢弃/保存失败、Caption 提交期间配置锁定，并收集 JavaScript 错误。
自动回归覆盖导航状态、任务筛选与状态语义；Curation 和 Caption 路由测试继续验证后端契约。

操作说明见[页面手册](data_platform_page_user_guide.md)和[Curation 契约](data_platform_unified_curation.md)。
